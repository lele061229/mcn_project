# 测试计划（从 2026-09-16 起）

> 配套阅读：《代码导读-20260916.md》了解系统结构，《学习任务.md》是学习线，本文是质量线。

## 一、先分清三种测试（按成本从低到高）

| 类型 | 谁做 | 测什么 | 现状 |
|---|---|---|---|
| 自动化回归 | 脚本 | 代码没被改坏（API/权限/UI 共 503 项） | ✅ 已有，每次改动全绿 |
| 自己冒烟测试 | 你 | 点开每个页面、每个按钮是否正常 | ⚠️ 部分，缺系统性清单 |
| 真人验收测试（UAT） | 同事/朋友 | 功能符不符合真实业务习惯、好不好用 | ❌ 还没开始 |

**你现在最缺的是后两种。** 自动化只能保证"没改坏"，不能发现"这功能根本没人这么用"。

## 二、自己冒烟测试（30 分钟，做一次）

用 6 个 demo 账号（登录页一键体验，密码都是 `demo123456`）按下面的剧本走一遍。**每一步记下：正常 / 异常 / 别扭**。

### 剧本：一条线索的一生（admin 或对应岗位操作）

1. **建**：新增线索（故意填一个超长渠道名、不填联系方式）→ 看表单校验
2. **分配**：管理员把线索分配给李婷（招募）→ 切 demo-recruit 登录，工作台能看到吗？
3. **SLA**：什么都不做等 1 分钟（或看已有演示线索 T0001）→ 即将超时提醒 → admin 催办 → 李婷收到通知
4. **跟进**：李婷写跟进记录 → 徽标变「已联系」
5. **转正式**：状态推到「已报名」→ 转正式达人 → 检查 convertedBy 留痕
6. **交接**：发起交接给运营王浩 → 切 demo-staff 确认 → owner 变更、opsBy 固化
7. **账号运营**：王浩维护达人账号数据（活跃度/粉丝数）→ 档案页能看到
8. **寄拍**：运营给达人建寄拍任务（任务归属=该达人的运营负责人）→ 任务在达人任务中心推进（寄拍状态机）→ 逾期标红
9. **看板**：admin 看板 → 渠道图、风险提醒、漏斗数字对不对

### 专项检查（容易翻车的点）

- [ ] 手机上打开（F12 切手机模式或真机）：线索页、工作台、看板布局
- [ ] 换浏览器（Chrome/Edge/手机浏览器）：localStorage 渠道是否还在（**换了会丢，属已知设计**）
- [ ] 两个浏览器同时登不同账号，一个人改数据另一个刷新看是否同步
- [ ] 直接改 URL 访问没权限的页面（如财务岗访问线索页）→ 应被拦截
- [ ] 断网/刷新后回到刚才的页面，状态是否丢失

## 三、找人测试（UAT，最重要的一步）

### 找谁

优先找**符合角色画像的人**：
- 有 MCN/电商运营经验的 → 演管理员和运营岗（他们对业务口径最敏感）
- 没用过后台系统的普通人 → 演招募岗或财务岗（测易用性，"不看说明书能不能会用"）
- 1～3 个人就够，不用多

### 给他们的测试说明（可直接复制发出去）

> 我做了一个 MCN 运营后台，地址：http://120.25.151.128:3000
> 你扮演【运营岗】，用 demo-staff / demo123456 登录（或告诉对方具体岗位）。
> 你的任务：管理分配给你的达人——写跟进、发起交接、建任务、维护账号数据。
> 不用看任何说明书，凭直觉操作。遇到看不懂、点不动、觉得别扭的地方，随手记下来。

**关键：不要提前讲解。** 测试的价值就在于看别人"零教学"能不能走通。

### 收集反馈的格式

让测试的人按三类反馈，越具体越好：
1. **Bug**：点了没反应 / 报错 / 数字不对（截图 + 做了什么操作）
2. **看不懂**：这个词/图标/按钮不明白什么意思
3. **别扭**：能用但很反人类（如"查个东西要点三层"）

## 四、Bug 记录与处理

建一个 `docs/测试反馈.md`（测试开始时我来建），每条格式：

```
[编号] [严重度 P0/P1/P2] 日期 | 测试人
现象：xxx
复现步骤：1. 2. 3.
状态：待修 / 已修(版本号) / 不修(原因)
```

- **P0**（数据丢失/权限漏洞/主链路走不通）→ 立即修
- **P1**（功能不对/明显别扭）→ 攒一批一起修
- **P2**（体验优化）→ 排队，不急

## 五、测试数据怎么处理

- 线上现在是演示数据（含 SLA 演示线索 T0001/T0010），**直接给测试的人用没问题**，他们乱改也不心疼
- UAT 结束后如果要清场重来：备份 db.json → 恢复到干净演示数据（跟我说一声，我来做）
- 正式启用前，再把真实业务数据导入（数据导入功能已就绪）

## 六、验收标准（什么时候算测完）

- [ ] 冒烟剧本 9 步全通，无 P0/P1
- [ ] 至少 1 位真人完成"一条线索的一生"，反馈 ≤5 条 P1
- [ ] 手机端核心三页（线索/工作台/看板）无布局崩坏
- [ ] 测试期间每次改动后，503 项自动化回归保持全绿
