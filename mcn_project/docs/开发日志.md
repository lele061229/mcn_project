## 2026-09-21 外部验收报告修复：权限收敛 + 前端假数据清除 + 实时刷新（v20260921b）

**背景**：GPT 外部验收交回 3×P0 + 6×P1。逐条用真实代码 + 线上数据复验后发现：**测试方的「ops 会话」实际登录的是 admin**（T0029.convertedById='admin'，真 ops 只能看到 4 条线索而非报告写的 20 条），3 条 P0 里有 2 条属于误报。但复验过程挖出了一个**报告没点破的真根因**：前端 `talent-leads.js` 内置了 19 条「金数据演示数据」（MOCK 数组），任何人打开页面都会看到这些库里根本不存在的线索——运营岗因此「看到他人线索/公海」，点开跟进还会 404。这才是「ops 数据越界」观感的真正来源。

**改动**：
1. **清除前端演示数据（P0 真根因）**：删除 `talent-leads.js` 的 MOCK 数组（19 条）与 `lead()` 工厂，`list` 改为 `reactive([])` 一律以服务端返回为准。修完后运营岗页面条数 = API 条数（10=10），彻底对齐。
2. **转正式达人权限收敛（P0）**：`POST /api/mvp/leads/:id/convert` 只允许主管（senior_ops/admin）；运营/招募一律 403 并提示走「提交审核」。前端「转为正式达人」按钮同步从 `isAdmin || owner===我` 收紧为 `isAdmin || isSenior`（桌面+移动两处）。
3. **交接确认后任务归属跟随（P0）**：达人交接确认且接收岗为 ops 时，同步把该达人名下所有任务的 `owner/ownerId` 改成新运营——此前任务中心仍显示旧负责人，与达人档案的 opsBy 自相矛盾。
4. **实时刷新探针（P1）**：新增 `GET /api/mvp/leads/version`（只返回可见范围内 `count + latestId`，与列表接口共用 `resolveScope + leadVisibleTo`，不额外放权）；前端每 8s 轮询，签名变化才拉全量并原地增量刷新 + 刷新交接收件箱；`visibilitychange` 回前台立即补一次。新报名/被分配/交接接收后列表与角标自动更新，不再需要手动 F5。
5. **报名手机号校验（P1）**：服务端 `POST /api/leads` 兜底校验 `^1[3-9]\d{9}$`（填了才校验）；recruit.html 提交前同口径前端拦截。
6. **账号运营口径收敛（P1）**：新增 `accEligible = isActive!==false && status∉[无效线索,已流失]`，5 处账号健康统计（团队异常数/异常达人卡/7天未更新/ops-alerts/工作台账号待办）与 `/api/mvp/accounts` 列表全部过滤——无效线索、已流失不再产生「账号待更新」噪音。
7. **SLA 残留清理（P1）**：管理员工作台「异常提醒」移除 SLA 超时项；senior 卡片「超时未处理线索」→「超 2 天未跟进线索」并在副标题注明与已停用的首次联系 SLA 无关。
8. **任务权限复核（未改动）**：验收报告的「ops 可操作他人任务」经复核**不成立**——`GET /api/tasks` 对 ops 用 `myTalentIds`（我名下达人）过滤，动作需 `mineTask || mineTalent`；且「运营审核自己名下达人的任务」是既有设计（check-crm-api 第 10 节锁定）。我曾试把审核/取消收紧到「任务归属人本人」，回归立刻红了 3 项（`ctx.position==='ops' && mineTalent` 被误伤），已还原。**教训：先证明 bug 存在，再动手改权限。**

**回归**：check-crm-api 249→**257**（新增 12.9 节：轮询探针 count 与列表一致性、ops 请求 scope=all 被降级、运营/招募 convert 403 + senior 放行、报名手机号 400）；check-biz-chain 28→**35**（新增 4.5 交接确认后任务归属跟随、4.6 转正权限收敛，并给脚本补了失败计数与非零退出码——此前它永远 exit 0）；check-split-smoke 15→**16**（转化链断言反转为「招募岗转化 403 / 管理员放行」）；check-crm-ui 49（种子数据补 1 条公海线索，配合 MOCK 移除后的「未分配」筛选断言；清理 4→5 条）。其余 26+44+39+75 不变。**全量基线 525 → 541**，本地 + 线上双绿。部署：v1/server.js + index.html/talent-leads.js/recruit.html → systemctl restart mcn-admin。

**学习价值**：①**验收报告要先「复现」再「修」**——3 条 P0 里有 2 条是测试方账号用错导致的误报，盲改会把正确的设计改坏（本次任务审核权限就差点被误杀）；②**UI 显示条数 ≠ API 返回条数时要警惕前端假数据**——前端内置种子数据是 demo 项目的常见遗留，会让所有行级权限测试「看起来漏」；③删功能时回归断言必须同步反转（本次 split-smoke 转化链、senior 卡片标签两处），且回归脚本自己也要能报失败（biz-chain 原来永远 exit 0）；④权限口径的「谁可以审」要区分「任务归属人」和「达人现负责人」——达人会交接，但任务跟着达人走，现负责人有权推进，这是业务设计不是漏洞。

## 2026-09-19 线索流转逻辑统一：付费孵化/免费招募双线 + 审核流（v20260921a）

**背景**：线索流转此前只有「分配→跟进」一条路，缺审核环节；SLA 前端入口与实际业务脱节；推广漏斗口径不统一；leadType 无区分。本次按业务方十条规格统一整条数据流：推广 → 报名 → 有效线索 → 分配 → 跟进 → 审核 → 新增达人。零依赖、不重构、role+position 双权限、行级权限全在服务端。

**改动**：
1. **leadType 双类型**：`paid_incubation`（付费孵化）/ `free_recruit`（免费招募，存量默认）；报名表单加类型单选；列表加类型筛选列。
2. **付费孵化自动分配+审核流**：报名选付费孵化 → 服务端自动分配负载最低的 ops（`opsLoadCandidates`，assignedBy='system'）→ 推 `new_paid_lead` 消息 → ops 跟进后「提交审核」（`POST /api/mvp/leads/:id/submit-review`）→ senior 工作台「付费孵化待审核」面板+卡片 → 审核通过（`review` action=approve）自动走 `promoteToTalent()` 转正式达人并推 `lead_approved`；要求补充则 reviewState='supplement' 退回并推 `lead_supplement`。senior 不再逐个手动分配，可重新分配。
3. **免费招募流程保持 recruit 价值**：新线索归 recruit 负责 → 沟通初筛 → senior 判断后分配 ops；招募工作台新线索面板过滤掉付费孵化线索。
4. **跟进登记权限**：ops 可填改跟进字段；senior_ops 主看+审核/要求补充/重新分配，不做日常跟进录入；「首次联系 SLA」前端入口全部移除（列表列/筛选/工作台卡/移动端徽标/更多菜单），历史字段保留但不再业务使用——`slaSweep` 改为 no-op（逻辑注释归档）。
5. **实时刷新**：铃铛轮询 60s→8s（`pollNotifs`），新消息轻 toast + 达人线索页 `syncFromDb(silent)` 原地增量刷新（不整页刷新）；`auto-assign-suggest` 负载口径升级（线索+达人+任务三类未完成数）。
6. **推广漏斗改口径**：主漏斗=推广活动→表单访问→有效线索→新增达人；campaigns 新增 `visits` 字段，promote 卡片换「表单访问量/有效线索数/有效线索转化率/新增达人成本」，旧字段保留只改展示。
7. **消息事件 5 个**：`new_paid_lead`/`lead_followup_submitted`/`lead_approved`/`lead_reassigned`（新旧负责人都收）/`lead_supplement`，pushMsg 白名单同步。
8. **check-crm-api 新增 12.8 节**（付费孵化自动分配+审核流 23 项断言）；`/api/leads` 报名限流加 loopback 豁免（回归不再撞 429）。

**回归**：check-crm-api 226→**249**、check-sla 40→**39**（SLA 卡移除断言反转）、其余 26+28+44+15+75 不变、check-crm-ui **49**（G 段招募工作台断言去掉 SLA 卡要求）。全量 **503 → 525**，本地+线上双绿。线上部署：v1/server.js + index.html/app.js/talent-leads.js/recruit.html，systemctl restart 后复跑全绿。修复 UI 回归 1 项过期断言（仍要求已删的「首次联系SLA超时数」卡，改为断言其不存在）。

**学习价值**：①**审核流挂接已有转化不变量**——审核通过不是自己写搬表代码，而是复用 `promoteToTalent()` 单一入口，两表口径永不漂移；②**过期断言比没断言更危险**——代码改了断言没改，绿灯会一直掩盖真实回归面（本次 G 段即例）；③限流器要给回归测试留 loopback 豁免，否则自动化自己把自己挡在门外（429 假失败）。
